# Spec Kit Flows Diary

## 2026-11-04
* **Update**: `/ocelle-run` rule 6: the orchestrator pushes the feature branch after each step with a clean tree (never `main`, no force-push without the operator's approval, never while a profile is still working). It replaces the no-push rule, which put work at risk in a container that can be reclaimed. `.claude/settings.json` allows `git push -u origin claude/…` and `--force-with-lease`, and denies pushes to `main` and plain `--force`/`-f`. Asked for by the operator during mission 002 (PR #19).
* **Finding**: a container restart lost a profile's uncommitted work: the phase 2 round 1 fix of mission 002. The orchestrator stashed the partial tree and the operator chose a clean rerun. Pushing after each step limits the loss to the step in progress.
* **Finding**: the analyst profile could not write `analysis-report.md` under the harness, so the orchestrator saved its report verbatim, with the operator's approval. Candidate: check the analyst's write permissions, or let it return the report for the orchestrator to commit as a named record.
* **Finding**: the flow has no step for a spec change decided at a phase review. Mission 002 had two: phase 3 R1-01 (CSP guarantee for the Storybook preview only) and phase 5 R1-01 (a closed `pairsList` part of a plant delta). Neither squad-fix nor spec-fix fits. The orchestrator recorded the decision alone (`reviews/phase-N/operator-decisions.md`), `planner-pim` amended the artifacts and added an open task, and the phase was re-implemented test-first and re-reviewed. Candidate: name this route in `/ocelle-run`, next to the addendum path of 2026-11-02.
* **Finding**: a `planner-pim` commit had no `Signed-off-by` trailer (phase 3 of mission 002) and was already pushed. Fixing it took `git rebase --signoff` and a force-push with lease, with the operator's approval. Later prompts ask every profile for `git commit -s`. Candidate: have the commit guard hook reject an unsigned commit.
* **Finding**: in phase 2 of mission 002 the implementer handed over without running the mutation gate; the review found the survivors. Candidate: `/speckit-story-implement` and `/speckit-story-fix` end with the mutation gate.
* **Finding**: `scaffold.sh` rejects files under `test/`, which conflicts with tasks that put a scaffold there (T008 of mission 002). A story file that matches the test pathspec (`*.stories.ts`) cannot go in a scaffold either, so the phase 3 implementer moved it to the red commit and its render code to a separate module. Candidate: say in the tasks template that test-pathspec files belong to the red commit.
* **Finding**: Stryker does not mutate inside `[…] as const`, so it generated no mutants in `packages/tokens/src/source.ts`. A phase 2 review claimed the source-table test "kills its value mutants" when there were none. Found by the phase 3 implementer and confirmed by the reviewer. Operator decision: drop `as const` (follow-up op). Candidate: the mutation gate flags a changed source file that yields zero mutants.
* **Finding**: once, `planner-pim` committed with `-c core.hooksPath=.git/hooks`, which steps around the configured hooks path. Candidate: the commit guard hook rejects a commit that overrides `core.hooksPath`.
* **Finding**: once, the orchestrator labelled its own suggestion as an "operator note" in a planner prompt, then retracted it. Only operator decisions may be presented as the operator's.
* **Finding**: sandbox limits in mission 002. The Playwright CDN is blocked, and the installed Chromium build differs from the one the pinned Playwright expects, so every role ran with `PLAYWRIGHT_BROWSERS_PATH` pointing at an aliased copy in the scratchpad. The container runs Node 22, not the pinned 26.13.0. Mutation runs exited 2 when the browser path was not set. Reading kitty-mission-ui (phase 6) needed the operator to approve attaching the repository.

## 2026-11-03
* **Update**: `/ocelle-land` gets a stop rule: one full landing round; later rounds only verify the earlier blocking findings and check for regressions, and new findings become follow-up issues unless they break a requirement with a reproduction or a red check. Asked for by the operator after the PR #18 landing pass re-opened phase 3 seven times (rounds 7 to 13), almost all for edge cases of one gate (mutation): each fresh review dug deeper into the same component, and nothing ended the loop.
* **Update**: `/ocelle-land` keeps the folded branch and `archive/<branch>-prefold` after a mission or op PR merges (operator decision L1-08: squash-merge, keep the evidence home); it never offers to delete them.
* **Finding**: Two review agents ran mutation testing at the same time in one checkout (phase 3 and phase 4 of mission 001). Stryker runs share `reports/mutation/mutation.json`, so one reviewer read the other's report (404 mutants instead of 353). Run mutation-heavy agents one at a time; a worktree per agent would also do.
* **Finding**: The phase 3 fix-9 round split files into 120-line chunks, but the greedy fill put the chunks of one file back in one shard, so the slow shard stayed as slow; the implementer reported it instead of claiming the aim was met. An operator round (phase 3 round 10) now keeps chunks of one file in separate shards. A cut also drops mutants whose node spans it (2 of 281 on csp.ts), accepted and recorded.
* **Update**: `/ocelle-land` folds mission and op branch history with `tooling/speckit/bin/fold-history.sh` (operator decision: "Evidence-preserving fold"). It keeps every commit the red/green evidence needs (base, scaffold and its parent, each red commit and its parent), folds the rest forward, remaps `base.sha`, `scaffold.sha` and `red-commits`, and writes `reviews/history-map.txt`. Tried on mission 001: 138 commits → 22, every tree identical, sign-off clean, `tdd-check.sh` passes on the new SHAs for phases 2, 3 and 5.
* **Creation**: `/ocelle-land`, the maintainer landing pass, adapted from the Spec Kitty era `ocelle-land` (spk-land-pr). Changes for the Spec Kit flow: viability triage goes through `triage-tara` and an approved triage record; branches are updated by merging `main`, never rebased or history-cleaned, because red/green evidence names commits by SHA; folds on mission and op PRs are operator rounds plus the story fix procedure; the second opinion is a fresh `reviewer-renata` landing review (new scope role `landing` in `scope-check.sh`); the merge exception is dropped (constitution: agents never merge); changelog entries per package only for public surface changes. Asked for by the operator.
* **Finding**: `summary.sh` counts only `R<n>-<m>` finding IDs as blocking, so the operator rounds of mission 001 (phase 3 rounds 3 and 5, phase 4 round 3, IDs `O<n>-<m>`) show 0 blocking findings in [the run summary](/runs/001-repository-foundation.md). The missing addendum path (2026-11-02) recurred twice: at the phase 4 shard timeout (operator chose a 250-line bound) and at the feature gate (operator chose to fix phase 3 notes in the pull request). A coverage-only fix (phase 3 round 5) had no red commit; the reviewer accepted hand-applied mutants as proof (round 6 note R6-01). Candidates: count any `<letter><n>-<m>` ID, an `addendum` command that records the operator round, and a red label for coverage-only fixes that records mutant evidence instead.
* **Finding**: GitHub runners were 1.5 to 3.4 times slower than the sandbox for mutation shards and varied by up to 2:49 between runs of the same code; local shard timings do not predict CI. Shard time follows mutants per file, not changed lines (phase 4 rounds 3 and 4).

Candidate: an `addendum` command in the story extension, and a red label for it. Also seen again: the analysis-fix loop is still improvised, and operator decisions are committed by an agent.
