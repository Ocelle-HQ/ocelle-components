| SPEC-1-01 | blocking | spec.md US2 scenario 4, FR-008, FR-012, Edge Cases "Root font size changed by the user" | US2-4 puts the compact hook on the root element and expects "the whole page is compact and the focus ring unchanged". Two things break it. (a) FR-008 makes the body use `--ocelle-font-size-md`, so a body rule overrides the size inherited from a compact `<html>` and the page is not compact. (b) If the compact hook sets `font-size` on `<html>`, every `rem` token in the page is rescaled to a 14 px basis: `--ocelle-target-min` (2.75rem) drops from 44 px to 38.5 px (constitution III), `h1` 30 px becomes about 26 px, the new 18 px token and all `space-*` tokens shrink, and the user's root font size setting is overridden. This contradicts the edge case, US3-1 and FR-015. | Say where the compact hook may go and what it does on `<html>`. Either forbid it on `<html>` (body or a screen container only), or say that on `<html>` it sets size and line height on `body` and leaves the root font size alone. Make FR-008 say the regular scale applies unless the element or an ancestor carries the compact hook. Add a scenario: with compact on the root, `--ocelle-target-min` and `h1` inside prose still compute to 44 px and 30 px. |
| SPEC-1-02 | blocking | spec.md Edge Cases "Nested hooks", FR-012, FR-015 | The rule "the innermost hook wins for size and line height" appears only as an edge case. No FR or scenario states it, so FR-022 never tests it. It also conflicts with the FRs. FR-015 sets no body size for prose (only line height and heading sizes), so a prose container inside a compact region has 14 px paragraphs at 1.65; #519's 26.4 px line height implies 16 px text. And a prose rule written on `p` matches a `p` inside a compact region nested in prose, so that paragraph gets 1.65 instead of the compact 1.5. That is the opposite of the edge case. | Add an FR and an acceptance scenario with concrete computed values for both nestings: the `font-size` and `line-height` of a `p` in prose inside compact, and of a `p` in compact inside prose. State whether prose sets a base size (`--ocelle-font-size-md`, as #519's 26.4 px implies). |
| SPEC-1-03 | blocking | spec.md SC-002, FR-022; US1 scenario 4 (borders), US1 scenario 6, US3 scenario 5, US4 scenario 2, FR-007 "MUST NOT" clauses | SC-002 requires that "each test was shown failing before its implementation". | SPEC-1-04 | blocking | spec.md US1 scenario 3, FR-010 | Without the stylesheet, `scroll-behavior` is already `auto`, and no FR has the base stylesheet declare a transition or animation. | SPEC-1-05 | blocking | spec.md US1 scenario 6 | "Renders without errors (every token reference has a safe fallback or none is needed)" has no observable outcome, because CSS raises no errors and the page always renders. The test could not fail. | Either delete the scenario and keep only the README statement, tested as a documentation check, or name computed values that must hold without `tokens.css` (for example `box-sizing: border-box`, body margin `0`, no `outline: none` on focus) and test those. |
| SPEC-1-06 | blocking | spec.md FR-002, FR-012, FR-015, FR-021; `gates/stylelint/token-only.ts` | FR-002 exempts "unitless numbers that are not lengths", and the lint allows unitless numbers on `line-height`.
