# Verification Quickstart

## Before a phase

Use the exact committed environment pins and `pnpm install --frozen-lockfile`. Record the full base and the real changing tests and implementation-story paths. When the composition is new, use a runnable behavior-neutral scaffold with real named targets and deterministic state. Keep index, mount, asset and fixture-availability proofs distinct from behavior. Require named post-action red assertions for the authoring request and focus, interview draft and retry, and selected-instance upgrade. Preserve the same assertions on green, then run canonical phase replay.

## Run the three proof layers

1. Run `pnpm run gate:unit-tests --project storybook-browser storybook/test/unit/browser/workflow-studio.test.ts`. Exercise the actual controls and authoritative host transitions. Run host preflight and ordinary scoped Mutation against the same base and candidate.
2. Run `pnpm run gate:unit-tests --project storybook-integration storybook/test/integration/workflow-studio.test.ts`. Verify built IDs and operate the actual iframe controls with keyboard and tap. Keep the browser wide while narrowing the recipe container, deliver the finding and observe the real drawer, the visible reviewer field and unchanged selection. At actual narrow sizes, measure finding, Add or Remove, and comparison or acceptance targets and keyboard rings in representative normal and forced-colour paths. Dismiss after a narrow pane hides a still-connected opener. Verify public close and the deep focus destination, including under reduced motion. Check local-only requests and fixture markup.
3. Run `pnpm run gate:unit-tests --project elements-browser packages/elements/test/browser/workflow-studio.test.ts` on the existing packaged browser setup. Use the same external hosts for authoring selection and binding, read-only run navigation and failed interview save, and opening and dismissing the upgrade comparison. Require the clean strict runtime result and verify `pnpm run gate:csp` separately.
4. Run `pnpm run gate:storybook-build`, record the exact final IDs and reconcile actual inventory and targeted Plant expectations. Use scoped Visual capture when the candidate CLI supports it. Otherwise use the full pinned harness and retain measured artifacts. Run `pnpm run gate:visual`, `pnpm run gate:axe` and `pnpm run gate:plants -- --affected <full-phase-base-sha>` against the exact candidate.

Compare independent authoritative before and after snapshots for movement, wiring, rejection and removal. For removal, inspect all deleted references and the unrelated surviving edge, and verify real focus on the successor or applicable fallback. For interview, verify both failed drafts, successful retry and the later review. For catalog, compare both pins and reviewers before, during and after explicit acceptance.

Reconcile the inventory and verify both historical phase evidence and current-main checks before landing. Keep all required CI.
