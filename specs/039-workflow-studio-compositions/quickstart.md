# Verification Quickstart

## Before a phase

Use the exact committed environment pins and `pnpm install --frozen-lockfile`. Record the full base, exact runnable consumers and the phase's shipped `implementation-story` path. Record the new non-test host and any new stylesheet as the neutral scaffold, with real named controls and deterministic state. Introduce the strict test HTML in the tests-only red and add the shipped CSF in implementation after red.

At the tests-only-red tip, run `red.sh N` and inspect the base and scaffold stages of `tdd-check.sh N`. Require named post-action failures in the in-process and strict harnesses for authoring requests and focus, interview draft and retry, and selected-instance upgrade. Confirm replay reaches the same sites on the scaffold with the test fixture overlay. On base, confirm matching applicable sites or a recorded collection-time missing-module result for the actual scaffold-added host, using the exact literal relative path in the test. At this checkpoint HEAD is expected to fail at the recorded red assertions. Require the full canonical replay to pass with the same assertions on green.

## Run the three proof layers

1. Run `pnpm run gate:unit-tests --project storybook-browser storybook/test/unit/browser/workflow-studio.test.ts`. Exercise the actual controls and authoritative host transitions. Run host preflight and ordinary scoped Mutation against the same base and candidate.
2. Run `pnpm run gate:unit-tests --project storybook-integration storybook/test/integration/workflow-studio.test.ts`. Record the missing exact built story ID as availability red, then verify that ID and operate the actual shipped iframe controls with keyboard and tap on green. Keep the browser wide while narrowing the recipe container, deliver the finding and observe the real drawer, the visible reviewer field and unchanged selection. At actual narrow sizes, measure finding, Add or Remove, and comparison or acceptance targets and keyboard rings in representative normal and forced-colour paths. Dismiss after a narrow pane hides a still-connected opener. Verify public close and the deep focus destination, including under reduced motion. Check local-only requests and fixture markup.
3. Run `pnpm run gate:unit-tests --project elements-browser packages/elements/test/browser/workflow-studio.test.ts` on the existing packaged browser setup. Use the same external hosts for authoring selection and binding, read-only run navigation and failed interview save, and opening and dismissing the upgrade comparison. Require the clean strict runtime result and verify `pnpm run gate:csp` separately.
4. Run `pnpm run gate:storybook-build`, record the exact final IDs and reconcile actual inventory and targeted Plant expectations. Use scoped Visual capture when the candidate CLI supports it. Otherwise use the full pinned harness and retain measured artifacts. Run `pnpm run gate:visual`, `pnpm run gate:axe` and `pnpm run gate:plants -- --affected <full-phase-base-sha>` against the exact candidate.

Compare independent authoritative before and after snapshots for movement, wiring, rejection and removal. For removal, inspect all deleted references and the unrelated surviving edge, and verify real focus on the successor or applicable fallback. For interview, verify both failed drafts, successful retry and the later review. For catalog, compare both pins and reviewers before, during and after explicit acceptance.

Reconcile the inventory and verify both historical phase evidence and current-main checks before landing. Keep all required CI.
