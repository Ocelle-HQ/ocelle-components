# Phase 2 plants (T025)

Evidence for contracts/checks.md § Pairing plants (the rows that name US1 scenarios) and the declaration-level style
plants of research.md R-17 for the two `css` templates of the phase, `src/ocelle-section-header.ts` and
`src/ocelle-card.ts`.

**Method** (005's working-tree method, `specs/005-icons-brand-mark/reviews/phase-4/plants.md`): each plant is an edit
of the element source (or of `src/card-context.ts` or `src/slot-state.ts`, where the row names them) in the working
tree at the green state of this phase. With the edit in place both harnesses run the phase's suites:

- in process (`elements`): `test/section-header.test.ts`, `test/card.test.ts`, `test/card-context.test.ts`,
  `test/entry-card-order.test.ts`, `test/entry-card-order-reverse.test.ts`;
- on the strict-CSP fixture (`elements-browser`): `test/browser/section-header.test.ts`, `test/browser/card.test.ts`,
  with the browser build and the mixed-copy card bundle rebuilt from the planted source by the global setup.

Then the file is restored. Nothing was committed with a plant and no test hook was added to source. The cells list
the scenarios that failed, by their label, with the number of failed tests first. A control run with no plant (a
comment line changed) failed no test in either harness.

Run on 2026-11-14 in this container, Chromium for Testing 1243 through `OCELLE_CHROMIUM_PATH`, on the green code with
the amended red commit's tests (`3829e84`).

**Result**: every style plant (56 declarations: 40 in the section header's template, 16 in the card's) and every
pairing plant (31) makes at least one scenario fail in each harness. The one exception is by design: the CSP plant (a
`style` attribute in the template) fails 41 fixture tests and no in-process test, since only the fixture pages are
served under the strict policy (FR-035); its guard is the fixture's. No declaration is recorded as equivalent.

Before the red commit, a read of each declaration against the scenarios showed five that no scenario would have
caught; scenarios were added for them in the red commit, and one of them found a defect:

- `.row { align-items: flex-start }`: the scenarios assert that each action is shorter than the heading column beside
  it (`partsOf`, "actionsShorterThanColumn"), so stretched actions fail.
- `:host([hidden])` of both elements: a hidden-host scenario per element.
- The card's `box-sizing: border-box`: the card scenario where the page sets the card's inline size.
- `.actions { flex-wrap: wrap }`: the "many actions at 320 px" scenario. It also showed that R-04's `flex: 0 0 auto` on
  the actions wrapper lets six actions overflow at 320 px; the wrapper keeps the initial `0 1 auto`
  (reviews/phase-2/notes.md), so that declaration is gone from the template and has no plant.

The rows of the pairing table are the contracts/checks.md rows for US1 (the "does not" outcome, then the plant), one
row per element where the contract's row applies to both.

`gate:plants` after the contrast counts changed: see the end of this file.
