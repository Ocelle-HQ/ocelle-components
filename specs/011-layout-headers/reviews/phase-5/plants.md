# Phase 5 plants (T047)

Evidence for contracts/checks.md § Pairing plants (the rows that name US4 scenarios, the rail or its landmark) and the
declaration-level style plants of research.md R-17 for the one `css` template of the phase,
`src/ocelle-personal-rail.ts`, and the role probe of contracts/checks.md § Role probe.

**Method** (005's working-tree method, `specs/005-icons-brand-mark/reviews/phase-4/plants.md`, as phases 2 to 4
applied it): each plant is an edit in the working tree at the green state of this phase, of `src/ocelle-personal-rail.ts`
unless the row names another file (`src/slot-state.ts`, the README, the fixture's stand-in stylesheet). With the edit
in place both harnesses run the phase's suite:

- in process (`elements`): `test/personal-rail.test.ts`;
- on the strict-CSP fixture (`elements-browser`): `test/browser/personal-rail.test.ts`, with the browser build rebuilt
  from the planted source by the global setup.

Then the file is restored. Nothing was committed with a plant and no test hook was added to source. A style plant
deletes one declaration (the template has no grouped selector). The cells list the scenarios that failed, by their
label, with the number of failed tests first. A control run with no plant (a comment line changed) failed no test in
either harness.

Run on 2026-11-15 in this container, Chromium for Testing 1243 through `OCELLE_CHROMIUM_PATH`, on the green code with
the red commit's tests, by a script that applies each plant, runs the two suites with Vitest's JSON reporter and
restores the file.

**Result**: every style plant (35: every declaration of the template) and every pairing plant makes at least one
scenario fail in each harness, but one, by design: the CSP plant (a `style` attribute in the template) fails 28
fixture tests and no in-process test, since only the fixture pages are served under the strict policy (FR-035). No
declaration and no pairing plant is recorded as equivalent.

Before the red commit, a first pass of seven pairing plants and a review of the planned declarations changed the red
tests three times (notes.md, "Before the red commit"): the template re-rendered per orientation failed no test until
US4-5 asserted that the shadow nodes stay the same; R-10's bottom-group `max-inline-size`, wrapping and
`justify-content` had no scenario until the "bottom group wider than half" scenario was added; and the horizontal
host's `min-block-size: auto` had none until US4-3 measured the rail in a container of definite block size. Two of
R-10's declarations are not in the template because no plant could catch them (notes.md).

## Which contract row each plant stands for

Every pairing plant below is the contract's planted defect for its row, except where this list names a substitute or
an addition (phase 4 review note R1-03):

- "Empty part adds no gap/padding (US4-6)": the contract's "wrapper of an empty slot not hidden", once per wrapper
  (primary, bottom).
- "Rail divider absent unless both groups are non-empty (US4-6)": as written.
- "Rail keeps orientation at every width (US4-4)": both of the contract's plants, the `@media (max-width: 720px)` flip
  and `container-type: inline-size` on the host with a `@container (max-width: 720px)` flip; each flips the layout
  column and the groups to a row.
- "Orientation change keeps focus (US4-5)": the contract's "template re-rendered with new nodes per orientation",
  written as Lit's `keyed(this.orientation, …)`. It is caught by US4-5's assertion that the shadow nodes are kept,
  not by the focus itself, which Chromium keeps (notes.md).
- "Layout variants hold in forced colours (US4-9)": the contract's "the layout rule moved inside
  `@media not (forced-colors: active)`", the horizontal `.layout { flex-direction: row }` rule.
- "Empty or invalid value not rewritten and treated as not set (US4-8, FR-006)": both of the contract's plants for the
  rail, the row keyed on `:host(:not([orientation="vertical"]))` and the element rewriting the value.
- "No attribute written on upgrade (FR-006, the rail's `orientation`)": the contract's initializer, set in the
  constructor (a class-field initializer would shadow Lit's accessor rather than reproduce the defect).
- "README orientation example uses an exclusive bound (US4-10)": as written, in the README.
- "No horizontal scroll at 320 px (US4-7)": the contract's `flex-wrap: nowrap` on the row (the horizontal groups).
- "No text clipped at 320 px (US4-7)": the contract's `overflow: hidden` plus `white-space: nowrap` on a wrapper (the
  layout container), and, as an addition, the same with `flex-wrap: nowrap` on the groups.
- "Blank host `aria-label` leaves no name (US4-11)", "No other node carries the landmark's name (US4-11)", "Host
  `aria-label` never written, rewritten or removed (FR-028)": as written. As in phase 4, an addition sets the role to
  `none` instead of `navigation`.
- "No event (FR-002)", "No tab stop added" (US4-5's tab order), "No CSP violation, no extra request (FR-035)": as
  written.
- "Gap follows content change": the contract names no US4 scenario in this row; the plant "slot state read once at
  first render only" (`src/slot-state.ts`) is an addition, caught by the no-event body, whose steps change the slots.
- "Vertical rail not held at a shorter flex-row or grid container's size (US4-2)": the `align-self: start` style plant
  in the first table.
- The US4-2 note under the contract's table: "the stand-in stylesheet's `color: inherit` dropped", in
  `test/browser/fixtures/rail-items.css` (the served copy on the fixture, the `?raw` copy in process).
- "Axe's role computation sees the host role (FR-028, R-11)" and "Internals key not in the manifest (R-11)": below.
