# Phase 3 plants (T032)

Evidence for contracts/checks.md § Pairing plants (the rows that name US2 scenarios or the page header) and the
declaration-level style plants of research.md R-17 for the one `css` template of the phase,
`src/ocelle-page-header.ts`.

**Method** (005's working-tree method, `specs/005-icons-brand-mark/reviews/phase-4/plants.md`, as phase 2 applied it):
each plant is an edit of `src/ocelle-page-header.ts` in the working tree at the green state of this phase. With the
edit in place both harnesses run the phase's suite:

- in process (`elements`): `test/page-header.test.ts`;
- on the strict-CSP fixture (`elements-browser`): `test/browser/page-header.test.ts`, with the browser build rebuilt
  from the planted source by the global setup.

Then the file is restored. Nothing was committed with a plant and no test hook was added to source. A style plant
deletes one declaration; for a grouped rule, one more plant per selector removes that selector from the group. The
cells list the scenarios that failed, by their label, with the number of failed tests first. A control run with no
plant (a comment line changed) failed no test in either harness.

Run on 2026-11-14 in this container, Chromium for Testing 1243 through `OCELLE_CHROMIUM_PATH`, on the green code with
the red commit's tests (`39df391`), by a script that applies each plant, runs the two suites with Vitest's JSON
reporter and restores the file. The first pass ran before the token-sentinel scenario gained its `span`-description
twin; the one plant it left uncaught (below) was run again with the twin, and every other plant had already failed at
least one scenario in each harness without it.

**Result**: every style plant (46 declarations and the 2 selectors of the template's one grouped rule) and every
pairing plant but the CSP plant (17) makes at least one scenario fail in each harness. The CSP plant (a `style`
attribute in the template) fails 20 fixture tests and no in-process test, by design: only the fixture pages are served
under the strict policy (FR-035), so its guard is the fixture's. No declaration is recorded as equivalent.

Before the red commit, this run found one plant no scenario caught: `::slotted([slot="description"])` in the
`display: block` group. A `p` description is a block already and the page's 16 px equals `--ocelle-font-size-md`, so
an inline `span` description sat where a block one would. The token-sentinel scenario gained a twin with a `span`
description (at the 15 px sentinel an inline `span` sits below the line's strut, off the heading column's gap), and the
plant then failed the sentinel scenario in both harnesses. The heading is not in the group: the `heading` slot takes a
heading element, which is a block already (reviews/phase-3/notes.md).

The mutation run on the same code (`gate:mutation -- --base a9a46eb`): 29 mutants on the changed lines of 2 files, none
survived; 3 compile errors (a block or arrow body emptied where the type needs a value), `src/index.ts` with no mutant
on its changed lines (an export), 0 equivalent records.
