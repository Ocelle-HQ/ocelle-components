| SPEC-2-01 | blocking | FR-025, FR-027, FR-030, FR-031; US3-7, US4-2, US4-4 | The pill's mode (static, button, link) follows the reflected `interactive` and `href`, which a host can change after render (a filter that becomes a link, a framework binding `href` to `""`). Only one direction is covered: FR-027 leaves `title` and ARIA on a static host, and FR-030 moves them off the host for good (012 FR-004: the host reads `null`, `removeAttribute` is a no-op, the value lives in the inner control and the `data-ocelle-moved-*` mirror). The spec does not say (1) what happens to moved values when the pill goes from interactive back to static: they are restored to the host, kept only in the mirror, or dropped. If they are dropped, a static pill loses its `title` (US3-7). (2) What happens to a mode-bound attribute in the other mode, or on a button/link switch. FR-030 moves `aria-pressed` in button mode only and `aria-current` in link mode only. 012 FR-009 moves `aria-current` in both modes and keeps `aria-pressed` off links. So `aria-current` on a button-mode pill and `aria-pressed` on a link-mode pill are unspecified (staying on a role-less host would give an axe finding, which FR-004 forbids). The same goes for `:state(pressed)` and `:state(current)` after a switch. Tests could be written either way. | State the transitions. For example: (a) values moved while interactive go back to the host (and the mirrors are removed) when the pill becomes static; (b) a mode-bound attribute set in the other mode is held, not applied, and applied when the mode matches, and its custom state follows the applied value only; or else (c) align with 012 FR-009 (`aria-current` moved in both modes) and say `aria-pressed` on a link-mode pill is unsupported and stays on the host, as 012's "attribute the element does not list" edge case documents. Add one acceptance scenario per transition. |
