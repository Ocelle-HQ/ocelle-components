| SPEC-3-01 | blocking | FR-012, US1-4, SC-004 | FR-012 says a run starts "in exactly these cases" (a) to (c), and "no other change" starts one. One common case is not listed: an indicator that is connected but not rendered and then becomes rendered. Examples: a hidden tab panel that is shown, a closed `<details>` that opens, a `hidden` or `display: none` ancestor that is removed. In CSS, an animation starts when the box is generated, so the run would start when the indicator appears. Under "exactly", it must not start, because its run was "started" at connection, possibly long before. These two readings call for different implementations: CSS only, or a clock kept per element. A test can be written either way. The parenthesis "(of `tone`, `label`, any other attribute or the theme)" can be read as the full list or as examples. Dashboards hide and show panels often, so the case is likely. | Say in FR-012 and US1-4 whether becoming rendered starts a run. One reading needs no state and matches the reconnection rule of (b): "(d) each time the indicator starts being rendered (it or an ancestor stops being `display: none`, hidden or in a closed `<details>`) while connected with `pulse` set, one run starts". Also say whether the parenthesis is the full list, and add the case to SC-004's list of starts. |
| SPEC-3-02 | blocking | FR-035 (c), US4-10, Edge Cases ("a filter that becomes a link") | A switch between button and link mode replaces the inner control: a `<button>` becomes an `<a>`, or the other way round (FR-030). The spec does not say where keyboard focus goes when the old control had focus at the switch. This happens, for example, when a host sets `href` in its activate or `click` handler. Removing the focused node sends focus to `body`, so a keyboard user loses their place (WCAG 2.4.3). Moving focus to the new control is the other reading. Becoming static while focused is not covered either. Planning could build either, and a test could be written for either. | Add to FR-035 and to US4-10: "if the inner control had focus at a button/link switch, the new inner control has focus afterwards, and a focus ring shows if one was visible before". Also state the static case, for example: "when the pill becomes static while focused, focus is lost as for a removed node, and the README tells hosts to move it". |
| SPEC-3-03 | operator | FR-030, FR-031, FR-035 (c), US4-4, US4-10, Edge Cases | The pill behaves differently from `ocelle-button` in two ways, while FR-030 says it follows 012 "as written" and reuses its helpers. (1) `aria-pressed` in link mode. 012's data model moves `aria-pressed` in both modes (removed from the host, stored and mirrored) and applies it in button mode only. The pill leaves it on the host in link mode, where axe flags it, and FR-035 (c) writes it back to the host when the pill switches to link mode. (2) `aria-pressed="mixed"`. 012 sets `:state(pressed)` only when the value is `"true"`. The pill sets it for `mixed` as well (FR-031). A host that styles `:state(pressed)` or binds `aria-pressed` on both elements gets different results for the same markup. Both behaviours are testable. Which one the library wants is a product choice. | Operator options. **(a)** Keep the pill as specified. The README names both differences from `ocelle-button`. **(b)** Make the pill match `ocelle-button`. In link mode, `aria-pressed` is moved and mirrored but not applied, so no `:state(pressed)` (FR-035 (c) drops its `aria-pressed` clause). `mixed` reaches the inner button as written, with no pressed look and no `:state(pressed)`. US4-4 and US4-10 change to match. **(c)** Keep the pill as specified, and record a follow-up op to align `ocelle-button` with the pill (`mixed` gives the state, `aria-pressed` stays on the host of a link). That op needs its own triage, since it changes 012's surface. |

| SPEC-3-05 | note | FR-030, FR-035; Dependencies ("Not changed here") | FR-030 reuses 012's helpers "rather than re-implementing them". 012's `MovedAttributes` (`control.ts`) moves every listed name on every change, reads mirrors back at the first connection, and has no per-mode set of names and no write-back to the host. So FR-035 (a) to (c) needs a change to the shared helper or a wrapper around it. The constraint is that `ocelle-button` and `ocelle-action-row` keep their behaviour. | Plan: say how the helper is extended (a per-mode name set and a release-to-host operation), and test that `ocelle-button`'s and `ocelle-action-row`'s passthrough tests still pass unchanged. |
| SPEC-3-06 | note | FR-027, FR-035 (a), US4-8, Edge Cases | FR-035 (a) writes moved values back to the host of a static pill, `aria-pressed="true"` or `"false"` included (US4-8). On a host with no role, axe reports `aria-pressed` as not allowed. It may also flag `aria-label` and `aria-labelledby` as prohibited on a generic element. In both cases the finding comes from the element's own write. The Edge Cases document only `aria-pressed` on a link-mode pill. Constitution III and FR-004 apply to stories, so the requirement stays testable, but hosts are not told. | Add an edge case and a README rule. ARIA states on a static pill, including those written back by FR-035 (a), are the host's to clear. A host clears `aria-pressed` with `removeAttribute` once the pill is static, or before making it static, by setting `""`. No story shows that state. |
| SPEC-3-07 | note | FR-035, FR-030 (012 FR-004 mirror read-back) | 012 reads a `data-ocelle-moved-*` mirror back as a stored value at upgrade. FR-035 says a static pill keeps passthrough values on the host with no mirror. The spec does not say what a pill that is static at upgrade does with a mirror it carries. This can happen with a copy taken while the pill was interactive, whose markup is then changed, or with server markup that drops `interactive`. The pill could write the mirror back to the host as the attribute, ignore it, or remove it. | State it in FR-035. One option: at upgrade, a static pill writes each mirror back as its host attribute (unless the host sets it, in which case the host's value wins) and removes the mirror, as in (a). |
