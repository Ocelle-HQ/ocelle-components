# Tasks — Anchored popover for compact controls

Start from the [approved plan](plan.md), [specification](spec.md), [element contract](contracts/element.md) and [verification contract](contracts/verification.md). The three phases are the ordered test-first units. A named owner is responsible for each shared file and generated result. The same owner can carry those files across sequential tasks. A `[P]` task can start in a separate pinned worktree once its prerequisites are complete. Its worker may change only the listed paths.

Before each phase, pin the clean base and run the applicable offline setup. For parallel red work, give all workers the same scaffold or phase pin, verify the disjoint signed returns with `tooling/speckit/bin/worktree-return-check.sh`, and join them in one tests-only commit. Run the canonical red before product behavior. Record assertion failures, including any expected scaffold/base distinction, and replay the same tests at green. The phase’s independent review and authorized fold follow the implementation task list. Preserve remapped evidence and replay after folding before starting the next phase.
