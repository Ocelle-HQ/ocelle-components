## Pilot evidence

1. **Mutation.** Pin exact head, base and toolchain. Choose one element-only `files` value from the normal `--plan`. Run `--shadow-grouped` and `--shadow-grouped --shadow-related-elements` serially on the same clean tree and selection. Capture receipts and exits separately. Verify identical config, ranges, unique mutant path/endpoints/mutator/replacement and complete outcomes including `NoCoverage`, then compare baseline test counts and elapsed time. If coverage or verdict differs, report it and keep full Mutation. Use Op 034’s mixed comparison only when the real plan supplies a mixed selector.
2. **Capture.** Build and inventory exact story IDs. Request the scoped workflow by adding the capture marker to the same-repository pilot PR body when authorized. Verify artifact head, base, ordered merge parents, run, attempt, both engines, known pin, expected files, themes and SHA-256s before adding the baseline PNGs. Retain full Visual CI for the finished candidate.
3. **Visual evidence.** Gather two complete successful runs on one same-repository PR with the same verified tooling base. The second revision changes only an authentic signed supported phase-review record. Verify fresh Sign-off and Sandbox paths on it. Request the observer against the earlier exact run and attempt and record eligibility or the reason no qualifying pair exists. Required checks still run for both revisions.

Record head, base, exact tested merge, run and attempt, scope, timing, total runner minutes, failed runs/retries and verdict or unavailable reason. At the end, compare locally actionable feedback to the final complete CI and update the mission retrospective with any next improvement. Count prospective reuse without treating it as executed savings.
