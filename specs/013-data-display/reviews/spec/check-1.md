## Operator question (SPEC-1-04)

FR-004 requires one description list (terms and definitions, in order) in the Chromium accessibility tree, and
SC-003 requires no serious axe finding, with the `ocelle-fact` child structure you chose (Q1 b). The flat tree puts
`ocelle-fact` hosts between the list and its terms, which Chromium and axe (`definition-list`, `dlitem`) may not
accept. If the plan's measurement shows the description list cannot be had cleanly, what should the plan do?

- **A. Keep Q1 (b), accept a fallback role:** each pair is exposed as a list item of a list, with the label as the
  item's leading text (or name); FR-004 is reworded to that structure.
- **B. Keep Q1 (b), require description-list semantics anyway:** the plan may use any structure that keeps the
  consumer's content unchanged (for example `ElementInternals` roles), and if none passes, the flow stops for you.
- **C. Fall back to Q1 (a):** the consumer slots `<dt>`/`<dd>` (or `<div>` groups) into `ocelle-facts`, and
  `ocelle-fact` is dropped from the surface.
- **D. Decide after measurement:** the plan's research measures first and the question comes back to you with the
  result before tasks.
