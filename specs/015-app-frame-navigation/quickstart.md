# Validation guide — app frame and navigation

Use the Node and pnpm versions in the root package. Install with `pnpm setup:online` or the repository's documented offline setup.

## Source browser tests

Run `pnpm gate:unit-tests`. Put the following behavior and branch assertions in `packages/elements/test/*.test.ts` in the mutation-selected `elements` project. Put touch-specific cases in `packages/elements/test/*.touch.test.ts` in `elements-touch`. Preserve red-first and old-code evidence through the story scripts, and use the element mutation gate for changed source.

1. Test each shell width just below, at and above both defaults with a fixed viewport. Repeat with token and explicit inputs, invalid inputs, equality and inverted bounds. Assert the actual tier, navigation availability and exact transition event count and details. Test RTL logical padding separately.
2. Open the narrow shell drawer by pointer, Enter and Space. Use real rail and sidebar destinations. Include two slotted destinations in the same focus scope whose sequential order differs from flat order. In a separate case give a competing destination or drawer control autofocus. Assert the first sequential destination is the deep active element before any Tab, then assert forward and backward wrapping. Verify the standalone drawer's existing autofocus behavior separately if its implementation changes.
3. Dismiss by Escape and the close control. Test a resize within narrow and across the threshold from a destination, menu trigger or close control. In a source browser case, focus a destination inside the real drawer and resize into collapsed to start its exit. Change the frame width again within collapsed and confirm the shell receives that observation before the drawer emits close. After the close event, assert that the same link has deep focus in the resulting navigation. Drive the exit and observation with the browser fixture's event or animation controls instead of elapsed-time sleeps. Assert the exact focus target, including when the destination is removed or no navigation remains. At a fixed width, switch from mission to project with focus on a disappearing rail link, both in the wide shell and in the open narrow drawer. Assert that focus moves to the first surviving sidebar destination and that the drawer stays open in the narrow case. Repeat with a surviving focused control and with no surviving sequential destination to exercise retention and the applicable main or drawer close fallback. Collapse an expanded context sidebar while focus is on an interactive head or footer control and assert that the control is hidden and focus moves to the first remaining destination or main. For each shell layout, exercise navigation at 320 px without horizontal page scrolling. Include a long translated product name and supplied actions. Assert focus visibility and the menu button's hit bounds meet the computed `--ocelle-target-min` on both axes.
4. Use a real context sidebar whose light-DOM section contains a nested list of nav items. Collapse and verify labels are visually compact, the full accessible name remains, bubble behavior works, and sidebar chrome is hidden. Expand, then open the narrow drawer and verify the same links regain their visible labels and sidebar chrome. Give an item a host compact setting and verify that it takes effect again after removing the item from shell-managed content. Check that focus/current state and normal link activation are preserved.
5. Inspect Chromium's accessibility tree for named rail and sidebar landmarks with distinct localized names in a mission frame. Check one occurrence per populated region in wide and open-drawer layouts, and absence when narrow and closed. Repeat with bare destination lists, an empty or omitted region, and the project and personal layouts.
6. Open a compact bubble by hover while focus is on a different control, including the drawer close control in an active drawer fixture with a standalone compact item. Assert the first Escape closes the bubble while leaving focus and drawer state intact. Assert the next Escape closes the drawer and restores focus. Separately open a newer modal while an older bubble is visible and assert the newer modal receives Escape. Cover pointer travel onto the bubble and keyboard focus, then repeat the name and visibility checks with long labels, forced colors and reduced motion.
7. Render the Desktop V2 inline nav group with several destinations and a separate action in the top bar. Check one named navigation landmark, ordered native links, current-page semantics, no landmark for empty items and normal keyboard and pointer navigation. At a constrained width assert wrapping, visible focus and no page overflow.
8. Tab to the skip control and activate it with a same-root selector and a cross-root reference. Assert deep focus and the subsequent Tab position. Cover precedence, a disconnected reference, an invalid selector and failed focus without losing focus on the skip control.

## Built output and visual checks

1. Add a built-shell test to `packages/elements/test/browser/` in the existing `elements-browser` project. Use its strict-CSP server, fixture recorders and externally loaded browser build, stylesheet and fixture module. Set independently sized frame widths using external stylesheet rules. Resize across a tier, open and dismiss the real drawer by keyboard, and activate the skip link. Assert the visible tier, drawer state and deep focus, plus the fixture's clean recording for policy violations, outside or failed requests, and console errors. Run it with `pnpm exec vitest run --project elements-browser packages/elements/test/browser/app-shell.test.ts`. Keep the behavioral branch assertions in the source projects.
2. Inspect all variants and states in both themes with the Storybook build from `pnpm gate:storybook-build`. Run `pnpm gate:manifest`, `pnpm gate:csp`, `pnpm gate:axe` and `pnpm gate:visual`. Refresh baselines through the pinned baseline workflow.
