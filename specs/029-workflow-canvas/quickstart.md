# Workflow canvas verification guide

On branch `029-workflow-canvas`, use the Node and pnpm versions pinned by the repository. Install from the existing toolchain cache with `pnpm run setup:offline`, or initialize it using the repository's documented online setup. The feature lives under `specs/029-workflow-canvas`. Run the following after their corresponding paths have landed in the phase.

## Exercise a controlled host

1. Start Storybook with `pnpm --dir storybook exec storybook dev`. Open Workflow Canvas and begin with Initial review, Publish and Revise. Tabs cross the node group once in each direction. With the group focused, arrows follow the supplied visible order and Enter or Space requests one selection.
2. Request an offscreen node by name. In a host that withholds the viewport, focus stays on the reveal control. Echo a viewport that puts the latest target in bounds and confirm its native action receives visible focus. Try two reveals before either update, and move focus away in a separate run. Supply coincident positions and reduce the zoom to produce overlap in a second fixture. Use the named reveal to raise a covered target and click its actual action. Verify Tab skips covered actions, host positions are unchanged, and reordering the host nodes restores the focused eligible action with zero requests.
3. Drag a node with an incoming and outgoing edge with a translated viewport at scale two. Its edges track the preview. Accept one move, reject another, then position it without dragging. Scroll an ancestor during capture at a stationary client point and verify the preview disappears with no request. Switch to read-only during a move and check for the same zero-request outcome. While a named authoring control is focused, clip its node and check focus and Tab order in both directions. Pan, zoom in, zoom out and Fit using the named controls.
4. Connect a named outcome by pointer, reassign by keyboard and disconnect by tap. Repeat the entire sequence for each input method. The host logs the operation and exact stable IDs and can reject a reassignment. During an edit, change its current destination in the host or switch to read-only and inspect focus and the request stream. These mode guards are verified in the phase that adds each edit.
5. In read-only mode, follow the named source, outcome and destination relationship by keyboard and then by tap. Swap two destinations, clip the current one and verify the named follow action still reaches the correct node with only the expected viewport request. Repeat read-only selection, remove the focused node, and compare the empty, narrow, long-label, combined error and selected, forced-colors and reduced-motion examples.
