# Workflow canvas verification guide

On branch `029-workflow-canvas`, use the Node and pnpm versions pinned by the repository. Install from the existing toolchain cache with `pnpm run setup:offline`, or initialize it using the repository's documented online setup. The feature lives under `specs/029-workflow-canvas`. Run the following after their corresponding paths have landed in the phase.

## Exercise a controlled host

1. Start Storybook with `pnpm --dir storybook exec storybook dev`. Open Workflow Canvas and begin with Initial review, Publish and Revise. Tabs cross the node group once in each direction. With the group focused, arrows follow the supplied visible order and Enter or Space requests one selection.
2. Request an offscreen node by name. In a host that withholds the viewport, focus stays on the reveal control. Inspect the accessibility tree and attempt direct focus while the node is unavailable. The native action is absent from the tree and focus stays visible. Accept a viewport that exposes the latest target through all clips. Confirm the same action and name reappear, the action receives visible focus and the stream contains only the expected reveal request. Try two reveals before either update, and move focus away in a separate run. Supply coincident positions and reduce the zoom to produce overlap in a second fixture. Raise the covered named target and click its actual action. Verify Tab skips covered actions, host positions are unchanged, and host reorder restores the focused eligible action with zero requests.
3. In a nested-shadow host fixture, clip a target in an enclosing scroll pane while it remains in the SVG bounds. Accept a map viewport update that leaves the target host-clipped. Confirm focus stays on a visible named control. Record unchanged pane scroll, the supplied viewport, and zero extra requests. Expose the target by host scroll and confirm focus can transfer only while the original initiator still owns focus. Verify the handoff adds neither scrolling nor requests. Clip an already-focused target and check recovery to a visible named control. In a separate run, move the pane out of view with a host class and put it back while keeping canvas inputs, sizes and scroll unchanged. Check that native Tab skips the hidden action and the accessibility tree omits it. Exercise focus or native activation before the observer runs and check for visible recovery and zero selection. On return, check that the same action and name are back in the accessibility tree and reachable by Tab. The host moves emit zero requests. Activate the restored action separately and check for one selection request.
4. Drag a node with an incoming and outgoing edge with a translated viewport at scale two. Its edges track the preview. Accept one move, reject another, then position it without dragging. Show a nonzero preview and scroll an enclosing shadow pane during capture at a stationary client point. While the pointer is still down, wait for the frame-driven update and verify the preview clears and supplied positions are displayed again. Release after the assertion and check for zero requests. Switch to read-only during a separate move and check for the same zero-request outcome. While a named authoring control is focused, clip its node and check focus and Tab order in both directions. Pan, zoom in, zoom out and Fit using the named controls.
5. Connect a named outcome by pointer, reassign by keyboard and disconnect by tap. Repeat the entire sequence for each input method. The host logs the operation and exact stable IDs and can reject a reassignment. During an edit, change its current destination in the host or switch to read-only and inspect focus and the request stream. These mode guards are verified in the phase that adds each edit.
6. In read-only mode, follow the named source, outcome and destination relationship by keyboard and then by tap. Swap two destinations, clip the current one and verify the named follow action still reaches the correct node with only the expected viewport request. Repeat read-only selection, remove the focused node, and compare the empty, narrow, long-label, combined error and selected, forced-colors and reduced-motion examples.

## Run the normal gates

- At the staged Phase 1 helper checkpoint run `pnpm run gate:unit-tests packages/elements/test/workflow-canvas-graph.test.ts packages/elements/test/workflow-canvas-navigation.test.ts`. Record the first combined helper green as the parallel timing endpoint. Record any still-red serial assertions by their exact red-proof identities and unfinished tasks before promotion.
- After serial integration, run `pnpm run gate:unit-tests packages/elements/test/workflow-canvas-graph.test.ts packages/elements/test/workflow-canvas-navigation.test.ts packages/elements/test/workflow-canvas.test.ts packages/elements/test/browser/workflow-canvas.test.ts`. Add `packages/elements/test/workflow-canvas.touch.test.ts` to the file list when that coverage lands. Record the integrated result separately from the helper checkpoint. These Unit commands take file paths directly after the script name.
- For each phase, record a canonical test-only red with `.specify/extensions/story/scripts/red.sh N phase`. Run `.specify/extensions/story/scripts/tdd-check.sh N` on the integrated green, with the exact shared test consumers in `reviews/phase-N/test-scope.txt` when needed. Record an unchanged replay and its actual reuse. The approved Op 028 guide is on branch `codex/028-within-phase-worktrees` at `dce21bac`. Use it for the first eligible in-phase task group.
- Build and verify with `pnpm run gate:typecheck`, `pnpm run gate:manifest`, `pnpm run gate:csp`, `pnpm run gate:storybook-build`, `pnpm run gate:visual`, and `pnpm run gate:axe`. Run the configured changed-source mutation and affected Plants from the recorded phase base. Record exact selections and outcomes.
- Keep collateral in local proof whenever hosted checks for its exact candidate are unavailable before phase review. For eligible Op 025 deferrals, record the candidate and each deferred project and file in its passing Unit plan and shard artifact, along with the required Visual regression or Accessibility check for the corresponding suite. If hosted CI used a synthetic merge, verify that it contains the candidate head and that the artifact names the tested merge revision. Gather this evidence before approving that phase. Run the full hosted checks for the final revision separately.
