# Implementation plan for an accessible workflow canvas

**Branch** `029-workflow-canvas` · **Date** 2026-11-23 · [Approved specification](spec.md) · [Triage](../../triage/029-workflow-canvas.md)

## Summary

Add the controlled `ocelle-workflow-canvas` primitive for Workflow Studio. It reuses the landed workflow node, projects host-supplied positions and connections onto an SVG surface, and exposes distinct selection, viewport, node-position and semantic connection requests. Native controls provide the non-drag paths and remain usable during read-only navigation where applicable. [Rendering and focus measurements](research.md) · [Consumer contract](contracts/workflow-canvas.md)

## Technical context

Use the pinned TypeScript, Lit and browser toolchain. Native SVG paths supply retained connections and HTML `foreignObject` supplies actual workflow-node and pointer targets inside the component. Use existing tokens and CSS adoption, in-process Chromium for focused proof and mutation, the built harness for strict CSP, real touch tests, and Storybook baselines. Data and persistence remain with the host. The renderer comparison exercised 12 and 96 nodes. Re-measure the shipped approach and report actual bundle delta and input response on those fixtures. Use the full required hosted checks on the final candidate.

## Project structure

- `packages/elements/src/ocelle-workflow-canvas.ts` owns the element, keyed nodes, render/update lifecycle, transient event dispatch and focus integration. `packages/elements/src/workflow-canvas-types.ts` defines the public data shapes and request details.
- `packages/elements/src/workflow-canvas-graph.ts` projects the ordered identities and drawable edges from host data. `packages/elements/src/workflow-canvas-navigation.ts` resolves visible traversal and recovery and tracks current reveal eligibility from primitive inputs. Neither slice imports the other. The element feeds DOM measurements and actual focus into these functions.
- `packages/elements/src/workflow-canvas-viewport.ts` handles graph-to-viewport geometry, inverse pointer deltas, fit and pan/zoom proposals. `packages/elements/src/workflow-canvas-edit.ts` handles the authoring connection session and validates it against the current authoritative connection.
- `packages/elements/test/workflow-canvas-graph.test.ts`, `packages/elements/test/workflow-canvas-navigation.test.ts` and `packages/elements/test/workflow-canvas.test.ts` run in the in-process `elements` project. Use `packages/elements/test/workflow-canvas.touch.test.ts` for real touch behavior in `elements-touch`. Both projects enter changed-source mutation. `packages/elements/test/browser/workflow-canvas.test.ts` and `packages/elements/test/browser/fixtures/workflow-canvas.html` verify the built API under strict CSP. Shared assertions or fixtures go in `packages/elements/test/scenarios/workflow-canvas.ts` only when both consumers genuinely exercise the same path.
- `storybook/stories/workflow-canvas.stories.ts` owns state fixtures and one owner generates the exact matching pairs under `storybook/baselines`. Update the actual manifest, export, README and exact inventory consumers from the phase base.

## Rendering and input boundaries

Render an SVG coordinate surface in canvas-local CSS pixels. Project node origins from the graph positions and current viewport. Use each node's screen-sized measured HTML extent to size its `foreignObject` and align edge anchors. A viewport scale changes spacing between origins and preserves native control size and readable text. Compute Fit from projected node extents, measured control sizes, padding and the routed bounds. Test a representative branching graph at the narrow width. Empty or temporarily unmeasurable graphs use the named canvas fallback and skip invalid geometry.

Determine on-map focus eligibility from the actual action and focus inset. Require containment in the effective clip, including the map, the browser viewport and [supported clipping ancestors](contracts/workflow-canvas.md#host-clipping) along the composed path. Follow assigned slots and cross each shadow root through its host. For supported convex clip paths, use native hit tests at each corner of the outline. For supported straight-edge polygons, also check whether a contour segment enters the outline. Use those checks for map focus, named reveal and visible fallback. Exclude actions whose footprint or focus inset intersects a later-painted card or pointer affordance. Recompute after rendering, on relevant resize and viewport changes, and on scroll at the enclosing scroll containers themselves. While idle, observe the action and focus bounds against the viewport and enclosing clips with `IntersectionObserver` or an equivalent position-change signal. Observe transitions into and out of full containment even for inert actions, so a host-only transform or reposition refreshes eligibility without a canvas input, resize or scroll. Treat the signal as a trigger to recompute live eligibility, including paint overlap. Update the observations when nodes or the composed path change, and remove them on disconnect.

Use a per-node HTML wrapper inside the `foreignObject`. Set it `inert` whenever the action's geometry is unavailable, clipped or covered, so that action is absent from sequential navigation, the accessibility tree and user activation and cannot receive native direct focus. Preserve the visual card, measured geometry and keyed action. Keep the corresponding on-map authoring hit affordances inactive while the node is unavailable. Before making a wrapper inert, capture any affected focus so the recovery rules can place it safely. Set the roving `.selectionTabIndex` before re-enabling the same wrapper after geometric eligibility is established. Recheck the live clip and hit bounds at native focus entry and immediately before a programmatic handoff. If a native entry races the observer and lands on an unavailable action, apply the same demotion and recovery. Check live eligibility in the map's capture path on activation of a node's native selection action, before its handler can emit a request. Stop an unavailable action there and leave an eligible action's native activation unchanged. The named navigation and relationship controls stay outside these wrappers and retain every reachable identity.

Keep graph order for keyboard traversal and a separate local SVG paint order. Default paint order follows the supplied nodes. The existing keyed `foreignObject` of a covered target within the effective clip can be raised above the covering nodes for a named reveal without emitting a viewport or edit request. Keep the raised node on top until another eligible named target is raised or the raised node leaves the graph. Asking to reveal a positioned but clipped target emits one viewport request. Use the exposed part of the map for the proposal when it can fit the action. A target still clipped by an enclosing pane stays unavailable even if the supplied viewport places it entirely inside the map. Neither raising nor focus recovery changes host positions, relations, or selection.

Keep SVG paths behind the real controls and hide the decorative edge group from accessibility. The named navigation outside the clipped map includes a read-only view of supplied source, outcome and destination relationships in both modes. Present distinguishable destination names and a native action to follow a destination using the existing named reveal. Derive these associations from valid graph IDs without filtering them by viewport clipping or paint overlap. All native named authoring controls also live outside the clipped map. Graph-local move and connection affordances are pointer-only SVG hit targets with no native focusable descendants and no place in the Tab sequence. Verify Tab and Shift+Tab after clipping their nodes, including when a corresponding named authoring control already has focus.

Preserve each #72 node's keyed instance through the render and pass only its supported selection, focus, content and state inputs. Set `.selectionTabIndex` on the node instance and call `focus({preventScroll:true})` after the actual action is ready. Inspect shadow focus and composed event paths. Handle arrows and endpoints only within the current node action group. Keep native Tab, reverse Tab and activation. Ensure a plain native click bubbling past the canvas cannot emit another application request.

The named reveal records its latest destination and focus generation before dispatch. Recheck both after host input, layout, paint and child update against the effective clip. An update which only reveals the earlier target leaves focus where it is. If both destinations are in the effective clip, only the latest target can receive the handoff after any required raise. Recheck the pending target on enclosing scroll if the initiating control still owns focus. Clear a pending reveal when focus departs, including departure followed by return.

Capture the exact active action, prior graph order and focus epoch before a render or eligibility update that may move, cover, clip, make inert or remove it. A keyed reorder, including a paint-only raise, can blur an action. When the same action survives and is eligible, retain or restore it before choosing a survivor. Restore only when the canvas's own move caused the focus loss within that render and no other control has received focus. For an ineligible or removed action, choose the eligible survivor in the prescribed order, then a named canvas control that is actually visible in the effective host clip. A reveal that cannot hand off keeps focus on its visible initiating control. If that control also becomes unavailable, use the visible named fallback. Leave external focus untouched. When the entire control surface is clipped, leave recovery to ordinary host navigation until a visible target is available. Use `preventScroll` on every canvas-programmatic handoff and fallback so recovery cannot move the host pane. Native user Tab and host scroll retain their normal behavior. Focus recovery emits zero requests.

Pointer panning starts on the map background. Dragging a node starts from a layout affordance distinct from its selection action. Pointer connection dragging starts from an outcome affordance and accepts a valid node destination. Dropping without a valid target cancels. Keep hit testing and visual guides internal. The named editor and non-drag layout and viewport controls give equivalent keyboard, click and tap operations.

For a captured gesture, freeze the map's invertible screen-to-local transform and viewport dimensions at pointer-down. Map both starting and later client points through that same transform. Check the live frame on animation frames only while capture is active, on pointer samples and immediately before dispatch. The frame check observes scroll in an enclosing shadow pane even when its event never reaches the canvas. On a change, consume the session, clear the preview and release capture so the next render reflects the supplied state even without a further pointer sample. Keep authoritative host values and emit zero requests. Stop the capture-scoped frame checks on completion, cancellation, lost capture and disconnect. A node move divides the resulting map-local delta by the captured scale. Apply the same cancellation on changed authoritative gesture inputs and validate the current mode before emitting each authoring request, including a host update before the DOM redraws. Consume the session before dispatch so capture loss, a synchronous host update or a duplicate release cannot publish an extra request.
