# Workflow canvas data model

[Specification](spec.md) · [Consumer contract](contracts/workflow-canvas.md)

## Authoritative inputs

| Entity | Fields and identity | Rules |
| --- | --- | --- |
| Graph | Ordered steps and connections | The host replaces input snapshots. Step order is independent of positions and drives bounded keyboard traversal, named choices and focus recovery. |
| Step | `id`, `label`, `kind`, `accountableRole`, ordered `outcomes`, optional `waiting`, `invalid` and readable `status` | One nonempty unique ID per graph. Display fields can change under that ID. The canvas retains the keyed workflow-node instance and passes descriptive outcome labels and states through its existing contract. |
| Outcome | `id` and `label` under a step | IDs are unique within the source step. Display labels can repeat and change. Use source context and the local outcome identifier to distinguish repeated labels. |
| Connection | `sourceId`, `outcomeId`, `destinationId` | A source and outcome pair admits at most one connection. Several sources may reach the same destination. Resolve a named relationship when both steps and the source outcome exist, even when the destination is clipped or lacks a position. The SVG path also needs both positions. The host owns domain validity and cycle policy. |
| Layout entry | `nodeId` and finite `x`, `y` | The pair is the rendered node's upper-left origin in graph coordinates. The host supplies one entry per displayed step. Ignore orphan layout entries. Unpositioned steps remain in named navigation without a visible graph action until the host supplies a position. |
| Viewport | Finite `x`, `y` and positive finite `scale` | Graph origin maps to local canvas coordinates `canvasX = graphX × scale + x` and analogously for Y. A position delta in graph units is the canvas-local pointer delta divided by the captured scale. |
| Selection and mode | `selectedNodeId` or null, and `author` or `read-only` | Host-owned and independent of focus. Default to empty graph and selection, identity viewport, and read-only mode. Only attached controls act on available inputs. |

Consumer data remains read-only to the element. Graph projections use maps or tuples keyed by IDs. IDs stay as data, including when they contain characters with selector or object-key syntax. Invalid or unavailable positions cannot enter transform arithmetic. Presentation coordinates are distinct from graph relations and from the current viewport.

## Local interaction state

- **Local paint order** starts in graph order with an optional raised ID for a named target. It affects only SVG stacking. A covered target inside the effective clip can become the raised node. Keep it raised until a different eligible named target is raised or it leaves the graph. Keyboard order always uses the supplied graph order over eligible actions.
- **Map action eligibility** requires the action and its focus inset to be measurable, unobscured, and inside the effective clip. The clip includes map, browser viewport and clipping ancestors across assigned slots and enclosing shadow hosts. Observe idle position changes that alter containment even with unchanged canvas inputs, sizes and scroll. Continue observing inert nodes so moving a pane back can restore the same action. Keep an unavailable node's HTML wrapper inert so the action cannot receive focus or user activation and is absent from accessibility navigation. Capture affected focus before making the wrapper inert. The named navigator retains the node's identity. Recompute eligibility and sequential participation before clearing inert. Recheck live eligibility on native focus entry, before programmatic focus and before the node's native activation handler can send selection, including when an observer notification is still pending.
- **Node focus** holds the current roving node ID within the group or none. Before a render or eligibility change, retain the old order, active native action and focus epoch. If the canvas's own keyed reorder caused focus loss and no other control received focus, restore the same surviving eligible action first. If that action is unavailable, prefer the next eligible survivor in the old order, then the previous one, then the actually visible named navigation control. Focus outside the affected controls remains in place. All canvas-programmatic focus uses `preventScroll`. If none of its controls is visible, the canvas leaves recovery to ordinary host navigation.
- **Pending reveal** holds the latest requested node ID, initiating control and local generation. For a positioned but clipped node, set it before emitting one viewport request. A later reveal replaces it. Before and after the rendering wait, verify the generation, current target and focus ownership. Handoff requires eligibility after both the map and enclosing host clipping are accounted for. If only the earlier target is visible, leave focus on the visible initiator. If both are eligible after any required raise, only the latest target may be focused. A locally in-bounds but host-clipped target stays unavailable and the initiating control or a visible named fallback keeps focus. Recheck after host scroll only while the initiator still owns focus. Clear the pending reveal on focus departure, target removal, or disconnect. A target already inside the effective clip uses the local paint and focus path without a viewport request.
- **Presentation gesture** holds the initiating pointer, node ID or viewport target, the captured inverse screen transform and map dimensions, starting authoritative layout and viewport, and transient proposal. Map both client samples through the captured transform and divide the local delta by the captured scale for a node move. Preview the node and its incident edges together. While capture is active, compare the live frame on animation frames even without pointer samples or a delivered scroll event. A changed transform or map size consumes the session, clears the preview and releases capture. Check the frame again before dispatch. Stop the frame checks on completion, cancellation, lost capture or disconnect. Cancel on capture loss, invalid target, changed authoritative basis or leaving authoring mode during a layout edit. Cancellation leaves supplied positions and connections intact and emits zero requests.
- **Connection edit** holds source ID, outcome ID, currently supplied destination at start, candidate destination, and initiating control. Compare those IDs and the authoritative source/outcome destination again immediately before publishing an intent. Renames leave their identities intact. Loss of an endpoint or outcome, or a change to the captured current destination, clears the edit. Compare the proposed destination to the current one to suppress no-op requests.
- **Viewport or edit completion** consumes its transient session before dispatch. A duplicate completion, pointer-capture loss after release, or host update inside an event listener then cannot publish again. Canceling an edit considers the initiating control, the source action, the survivor order and the named canvas control, in that order. Each recovery target must be visibly eligible in the effective host clip. Focus outside the affected controls stays where the user left it.

Selection requests, viewport poses, position proposals and connection intents are separate records. The host can replace any corresponding input after observing one request. Component updates and focus recovery themselves publish no requests. A declined edit needs no rollback of graph state because the element renders the supplied graph and discards its transient preview.
