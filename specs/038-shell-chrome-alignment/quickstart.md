# Shell Chrome Validation

## Setup

Use the repository-pinned Node, pnpm, Chromium and theme fonts. Install with `pnpm install --frozen-lockfile`, then use the standard `.github/actions/setup` build/browser inputs or the corresponding documented local setup. Record the exact phase base and tested head.

## Run the targeted checks first

- Phase 1. Run `pnpm run gate:unit-tests --project elements packages/elements/test/top-bar.test.ts` and the built app-shell test in the `elements-browser` project. On a settled visible bar, assert zero top-bar lower-divider pixels in light, dark and forced colours and separately assert the fixture-owned pane separator's visible pixels at its pane boundary in each mode. Keep the failing zero-divider assertion against the pinned old source and the same assertions green after removal. Recheck the existing native menu and actions.
- Phase 2. Run the in-process and built personal-rail tests using their corresponding Vitest projects. The shared scenarios compare fixed-height, populated default and opt-in rails with omitted orientation and verify the opt-in also applies with empty and other attribute values without rewriting them. Check the opt-in's bottom gap, spare height before the divider, unchanged destination boxes and order, empty groups and focused orientation changes. In forced colours compare the same fixed-height rails and verify the system-colour divider pixels as well as their placement.
- Phase 3. Run the direct top-bar, app-shell-actions and app-shell-reflow tests in `elements` and the built app-shell test in `elements-browser`. Exercise the badge directly and through the shell with and without content. At a true 320 CSS px viewport use a long title, short text badge, real navigation and menu in the narrow shell and the existing Settings action. Verify names, order and activation using trusted keyboard input, no page overflow, menu hit area on both axes, and the full rendered focus indicator after Tab reaches each control. Run that accessory specimen in forced colours as well and verify visible badge text and both complete focus indicators.
- Run `pnpm run gate:csp`. In the built strict-CSP app-shell browser test, serve `packages/elements/test/browser/fixtures/app-shell.html` with its external `app-shell.css` and `app-shell.js`. Verify one composed and accessible badge in the narrow shell and use the keyboard to operate the real menu and Settings action. Check one Settings activation and collect the clean fixture record after the interactions. Keep the existing built drawer and skip-link regression. The standard Storybook preview supplies visual and Axe evidence.
