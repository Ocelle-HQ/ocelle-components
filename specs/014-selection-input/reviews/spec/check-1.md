## Operator questions

- **Q1 (SPEC-1-07). Which URLs does `ocelle-link` navigate to?**
  (a) Resolve `href` against the document base, and navigate only when the resolved protocol is `http:` or `https:`.
  Relative links in a custom-scheme webview then never navigate, and the host handles the event.
  (b) As (a), but also navigate when the resolved protocol equals the document's own protocol, so relative links work
  in Kitty Desktop's custom-scheme webview.
  (c) Navigate any resolved URL except a deny-list (`javascript:`, `data:`, `vbscript:`, `blob:`).
  (d) Check the written `href` as FR-047 says now: navigate when it starts with `http:` or `https:` or has no scheme,
  with the string trimmed and tabs and newlines removed before the check.
- **Q2 (SPEC-1-08). How does a modified activation of `ocelle-link` with `href` behave (Ctrl/Cmd-click, Shift-click,
  middle-click)?**
  (a) Emit no event and keep the browser's own behaviour (new tab or window). Only plain activations emit.
  (b) Always emit `ocelle-link-activate`, and add the modifier keys and the button to `detail`. The host decides, and
  native behaviour follows unless the event is cancelled.
  (c) Treat them like a plain activation: emit, then navigate in the same window unless cancelled.
- **Q3 (SPEC-1-09). With #10 unmerged, how far may this feature go?**
  (a) Phases may be implemented and the feature may merge with baselines and axe recorded as pending #10. A follow-up
  op adds them when #10 merges.
  (b) Phases may be implemented now, but the feature's pull request merges only after #10 merges and the baselines and
  axe gates pass, as #14's done-when requires.
  (c) Implementation waits for #10 to merge, as the operator ruled for 008.
